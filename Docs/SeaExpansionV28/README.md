# 归潮湾 v28：海域扩建与海湾规划

v28 基于 v27 的港湾、鱼类和 v26.2 水面，新增独立场景 `CoastSeaExpansionV28.unity`，程序 `Builds/SeaExpansionV28/Guichao-SeaExpansionV28.exe`。桌面“深海灯塔－最新版”和“深海灯塔-海域扩建与建造-v28”进入此版；旧 v27 程序及入口保留。产品名与原正常存档目录沿用 v21，建造布局另存 `sea-bay-expansion-v28.json`。

## 游玩与操作

| 操作 | 作用 |
|---|---|
| G | 进入或退出海湾规划，当前活动需先结束 |
| WASD | 常规航行/步行；规划时仅平移镜头 |
| 滚轮 | 规划视野缩放 10–38 |
| 1 / 2 / 3 / 4 | 木栈桥 / 马灯 / 珊瑚花园 / 捕蟹浮标笼 |
| R | 设施旋转 90° |
| 左键 | 验证当前位置、水深、碰撞与物资后建造 |
| 右键 | 拆除设施并返还相应建材 |
| Esc | 退出规划；正常游戏中仍沿用暂停/关闭窗口逻辑 |
| F7 / F6 / F8 / F9 | 正常模式下水面调参 / 水面对照 / v27装饰对照 / 帧率 |

规划时原 HUD 隐藏、船只停泊，退出后恢复镜头、HUD 与原有步行/航行状态。建造界面覆盖区不会触发放置，不接收开船、投钩等输入。站在栈桥上的角色不能拆除脚下栈桥。

## 实际接入

航行范围从 `[-6,34] × [-23,32]` 扩至 `[-10,86] × [-50,66]`，矩形面积由 2,200 m² 至 11,136 m²，约 5.06 倍。这是边界面积，不代表可建造面积全部扩大五倍。新旧惯性与后备推进路径、恢复坐标和边界处保存坐标一起同步，严格限定 v28 场景或显式 `-bay-v28`；旧场景保留原边界。

实际水面网格为 300 m × 300 m，以支持规划镜头在新边界附近缩放；不用拉伸 Transform 改变波浪幅度。波纹仍在世界坐标求值。新增连续沙底网格融合 A 暖沙浅坪、B 南北珊瑚礁坪与 C 新月环礁，C 区保留向东的深水潟湖开口。新海床参与深度、法线及物理采样，水面光学默认值 `.92 / 1.85 / 72 / .95` 保留。

2m 网格原点依现有码头落在 `(-1, 2.4)`，示范栈桥与旧码头约 0.8m 的步行高度对齐，不直接采用原包中悬空的旧坐标。固定接口格 `(0,0)` 单独允许与原栈桥重叠，其他格保留岸礁/设施碰撞限制，避免因自动跳过接口而断路。木桩、海带、珊瑚底座及捕蟹笼按实际水深落根；放置检查覆盖四角、岸礁、船体和上下船保留区。深水范围可航行，但超出桩基水深不能建设。

复用 v27 的旧木纹、开放框架灯笼、分叉珊瑚和绿色海带，以及既有扫描岩石；未生成一套风格不同的占位球体。船外新增木板、木桩、蟹笼为可编辑 C# 几何，静态同材质部件在创建时合并。四种游标缓存复用，无碰撞；拆除设施释放专属合并网格。马灯最多启用四盏新增无阴影灯，位置同步给独立 v28 表面着色器。

建材起始为浮木 24、石 16、苗 12、黄铜 8。示范布局只在首次无建造存档时创建，拆空后不会重生。保存采用临时文件与原子替换；损坏或未来版本布局不自动覆盖。测试补给按钮仅在自动验收模式出现，不作为正式资源获取循环。

原包完整保存在 `Tools/SeaExpansionV28/OriginalInputs/`。适配代码按输入、几何、设施、UI、验收拆为 partial 文件；常规重建入口 `Deepsea.Editor.SeaBayExpansionBuildV28.Build`。`Tools/SeaExpansionV28/Rebuild-Bay.ps1` 默认仅校验已接纳输入，`-Build` 构建；显式 `-Prepare` 才从 v27 重建 v28 场景。

## 范围

本轮是空间扩建与建造样板。捕蟹笼目前为可建造实体与浮标表现，尚无自动产蟹、收取奖励、资源补给或完整经营经济；未增加外海新鱼点、外海建筑登船入口或自由岛屿探索。原有码头上下船位置保留，栈桥是实体可行走网格，不将放置成功等同于所有自由布局的步行连通性保证。

新的宽视野会暴露原地图部分边缘和既有生态分布；新增区域尚未完成整体环境精修。检查通过不代表用户已认可美术、目标图匹配、全地图长期性能或 4K 高刷。

## 验证与测量

正式运行证据 `Verification/bay-v28-review06`：48 项通过，运行错误/警告为 0；包括扩建边界以外实际推进、边界保存回读、四类设施放置/重复拒绝/拆除退款、资源不足、布局回读、空布局保持为空、原上下船与小人连续走到新栈桥。最终布局 10 个示范设施。测试在游戏加载前同时隔离玩家存档与建造存档。

Intel Arc 130T，1920×1080 可见窗口，每镜头 480 帧短时采样：

| 镜头 | 平均 FPS | P95 帧时间 |
|---|---:|---:|
| 扩建海湾宽视野，含常规 HUD | 105.53 | 10.74 ms |
| 规划全景，含网格和建造 UI | 108.58 | 10.23 ms |

镜头比 v27 原性能样本更广，不能据此直接比较新旧开销；以上不代表长期稳定、全地图或 4K 性能。最终增量构建有 1 项历史 API 警告，本轮完整构建曾有 24 项既有警告，不称全工程无警告。新 Shader 编译错误为 0。

首轮初始化空引用、第二轮材质与边界保存失败、第四轮接口缺失导致步行不通，以及输入驱动未加载模块/前台保护中止，均保留为草稿，不作为最终交付依据。

Windows 原生输入证据 `Verification/bay-v28-native05`：12 项通过，覆盖 G 进入/退出、W 漫游且船不动、3 选择、R 旋转、实际鼠标左键建造和右键拆除。该报告的性能/地形计数字段未采样，数值 0 不作性能依据。驱动在确认目标进程取得前台后才发输入，按客户端尺寸映射坐标。此前错误测试曾取用变化中的悬停格，已改为局部固定目标格。

最终旧文件、正常存档与旧 v27 程序哈希核对见 `result.json` 的 baseline 字段。旧核心源码仅三文件增加受 v28 场景限制的边界、输入/镜头、临时存档及调参互斥钩子，其余已记录旧文件保持原哈希。
